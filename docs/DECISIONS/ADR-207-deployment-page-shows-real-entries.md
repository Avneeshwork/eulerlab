# ADR-207 — The Deployment page shows only real entries

**Context.** Operator, 2026-11-16: clean the Live → Deployment page and remove what is not real. It showed 13 paper cards (7 stopped or halted, most never traded), 86 "passed the gate" rows (19 with no stored report, 17 paper cannot run) and long notes on every card.
**Options.** (a) Delete stopped deployments and unreported cards; (b) hide them behind a toggle, decided from data the page already has; (c) leave it.
**Choice.** (b). Full cards only for active books; stopped and halted books fold into one line each under "Show N stopped or halted". A gate row shows by default only if it has a stored report (`table.period` set) and no `deploy_blocker`, best 15 by Sharpe (realistic fills where the server has it, ADR-205); "Show all" lists every row with why it is not ready. Card warnings show their first sentence, the rest on hover. Operator, same day: each paper book links to its strategy's backtest report, showing its Sharpe and annual return; add/withdraw folds behind a button; the real-money panel is one header, one input row and one action row. Later the same day: the "code changed since it was deployed" lock note is hidden from cards (still enforced by the runner), loss limits open from a button that turns red when the reduce-only level is hit, and gate rows show the report's annual return, trades and test years with a Report button.
**Why.** Nothing is deleted, and a strategy whose report lands later (the factor cards being rebacktested) appears without another change.
**Cost if wrong.** A useful row ranked 16th or lower is one click away rather than on screen.
**Strategies page, same day.** Operator: keep only real ones, the rest in the archive. A strategy with no stored report counts as archived in the view (`Library.tsx: inArchive`); its `archived` flag is not written, so it returns to the main list once its report lands. Backtest and Deploy sit side by side.
**Paper floor, same day.** Operator: "less than .5 sharpe should not be in paper". The workbench hides gate rows below 0.5 (realistic Sharpe where measured) and disables Deploy and Start paper for them (`web/lib/paperFloor.ts`). The gate itself is left to the rebacktest thread; server enforcement is T-4646.
**Killed panel, same day.** Operator: "if strategy is killed once show in 1 row". While its kill switch is tripped the real-money panel is one line: name, Killed, the reason, how to clear it, and the backtest link.
