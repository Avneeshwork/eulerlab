# ADR-104: A knowledge keeper agent keeps the metrics library current and growing

- **Context:** On 2026-10-31 the operator asked to "setup a system to keep updating knowledge or increase knowledge base over time and lets start now", the same day the metrics library (ADR-103) was written. Its "what is normal" lines age from the day they are written. Its rule pages describe regulations that SEBI, RBI and NSE change by circular, and the regulatory monitor `docs/EVENTS/` has promised since August was never built. Nothing recorded which questions the library failed to answer.
- **Options:** (a) Re-run the library by hand every few months. (b) An agent that rewrites the pages itself. (c) An agent that refreshes computed figures itself, but only proposes text changes: watch official feeds, find gaps, draft updates from source material, and let the operator approve each one.
- **Choice:** (c), the `knowledge_keeper` agent. Daily, in `make agents-close`: recompute normals into `data/derived/metric_normals.json`, and land the SEBI, RBI (press releases, notifications) and NSE circulars RSS feeds. New items are linked to pages by title keywords in `config/knowledge_sources.yaml`. Weekly (`mode=weekly`, `make agents-weekly`): assumptions past their recheck date, aged pages, market-context sections with no page, lookups the assistant made that found no page (`explain_metric` logs them), and up to three model-drafted page updates. Drafts are made from the page plus the new material only, pass the grounding check (ADR-088), and wait in the inbox. `make metrics-accept DRAFT=...` is the only way a draft reaches `docs/`.
- **Why:** Computed figures can be refreshed safely because they come from held data with a knowledge time. Text cannot: a model rewriting the reference its own answers are checked against would make the check circular. The operator stays the editor, the agent does the reading. A question with no page gets a proposal, not a drafted page, because there is no source to draft it from.
- **Cost if wrong:** Feed formats change: a feed that stops parsing is reported as an alert, never silently skipped. Title matching misses a rule change worded unexpectedly, and the unlinked titles are kept in each run's output so a missed one can be found. The keeper writes outside its run folder: `data/derived/metric_normals.json`, `data/derived/regwatch_items.jsonl` (append-only) and `data/landing/regwatch/` (immutable). Those are data, not docs. 12 model requests a day at most.
