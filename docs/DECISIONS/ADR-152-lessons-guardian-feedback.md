# ADR-152 — Agents that learn, a guardian that stops them, and one feedback desk

**Context.** Operator, 2026-11-08: the agents should learn over time, check their work against data instead of making things up, fix their own failures, stop themselves when they do wrong, and run as an organisation where the operator only gives feedback. An audit found the safety parts mostly built (boundaries, grounding, the doctor, the kill switch) but three gaps: nothing an agent learned reached its next run except the lab's own memory; nothing stopped an agent that kept failing or made up figures, beyond one evaluation that switches off the knowledge agent; and the operator's words reached agents only as briefs or typed tasks, with no record of what became of them. The operator approved the plan ("keep building strategies and process to deploy parallely").

**Options.** A model-run memory (embeddings, a model choosing what to remember); a fixed store with keyword retrieval; or nothing beyond HISTORY.md, which agents never read.

**Choice.** `agents/lessons.py`: an append-only store, seeded from every numbered HISTORY entry and from the gate's and autopilot's findings; the relevant few (operator lessons first, then lessons naming the agent, then keyword overlap of at least two words) ride on every model request through `Context.ask`, and each output records which lessons it carried. A lesson can name a code check: two exist (price-only intraday rules, research 153-176; shorting results-morning gap-downs, H-0177), and the autopilot drops a card that breaks one before anything runs. `agents/guardian.py` runs after the doctor on every run, with five fixed rules: a changed `mandate.yaml` or `gates.py` halts every agent; three answers in a day withheld for unsupported figures suspend the agent; three failed runs in a row are held (told and written as a lesson, not stopped, so the doctor's fixes can still heal it and the watchdog keeps reporting it stuck); more ledger entries in 7 days than `gate_entries_per_week` suspends the autopilot; a screened net Sharpe above 3 is held (no switch flipped, a lesson written, the readiness checklist blocks a pilot). A Telegram word `feedback` is added beside `instruct`: it writes a lesson or a head's task, never anything near orders, the gate or limits. A halt is lifted only by `make agents-resume REASON=...`; a suspension only by the operator's switch. `agents/feedback.py`: `make feedback TEXT=...` or Telegram `feedback ...`; a rule (never, always, avoid...) becomes an operator lesson, anything else a task for the head chosen by keywords, and every message is logged with where it went.

**Why.** Retrieval and routing by fixed rules can be predicted and tested; a model choosing them would itself need checking. Enforced lessons cannot be ignored by a model; prompt lessons stop it proposing them. The guardian copies the kill switch's asymmetry: tripping is cheap, clearing is the operator's.

**Cost if wrong.** Keyword retrieval misses a lesson worded differently from the prompt, and six lessons add about 400 tokens a request. The guardian's thresholds (3 failures, 3 withheld answers, Sharpe 3) are chosen by hand (A-125). Editing the mandate yourself halts every agent until you run `make agents-resume`, by design. The guardian reads the autopilot's gate log as a file, not the ledger, so entries made outside the autopilot are not counted.
