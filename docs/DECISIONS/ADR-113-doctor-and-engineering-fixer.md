# ADR-113: A doctor checks every agent run, and the engineering agent fixes code problems one file at a time on a branch

- **Context:** On 2026-11-01 the operator asked that agents "have intelligence and capability to fix issues coming up", and that code problems go to the engineering agent "using most intelligent model", knowing the whole architecture, changing "only suspected file nothing else", with low latency and a running code quality check. Until now a crashed run, a run killed by the Mac sleeping, or a too-good backtest waited for the operator to notice it on a card.
- **Options:** (a) Leave fixing to the operator's coding sessions. (b) Let an agent edit the checkout and run the tests. (c) A doctor with a fixed list of safe remedies after every run, and an engineering fixer that works only on its own branch, in a git worktree, on one file and its test, and leaves a green fix for the operator to merge with one command.
- **Choice:** (c). `agents/doctor.py` runs after every agent run (`runtime.run`) and never raises: it closes runs with no step for 3 hours, flags robust Sharpe above 3 or IC t above 10, notes a model that did not answer, hands data refusals to the data agent, and queues a crash for engineering under the deepest `src/eulerlab` frame of its traceback. `devtools/fixer.py` (the only module allowed to run git and the checks, imported only by `engineering.py`) refuses the never-touch list before asking a model, gives Claude Opus the rules, the ARCHITECTURE sections naming the module, the file, its test and the error, accepts a diff naming only that file and its test, runs ruff, ruff format, mypy, the file's tests and the engine self-test, retries once with the failures, then commits and pushes `agent-fix/<id>`. `make agents-close` runs the daily quality check (ruff, mypy, pytest) and works the queue; `make agent-fix-apply ID=<id>` is the operator's merge.
- **Why:** The operator chose one tap to merge (recommended) over auto-merge pending their answer; an agent's code reaching the branch the live system runs from without a human look is the step that cannot be taken back. One file, a worktree and fixed commands keep a bad answer from spreading, and the checks reuse the checkout's environment so a fix takes about a minute.
- **Cost if wrong:** About $0.45 per model request at listed Opus prices, at most 20 a day (A-090). A crash whose cause is in a second file is reported "no fix" or "diff too wide" and still needs a person. A file over about 60,000 characters is cut in the prompt and may come back incomplete; the checks then fail and the problem goes to the operator.
