# ADR-175 — Rules become expressions over point-in-time tables; entries come from arrays, numbers still from the engine's books

**Date:** 2026-11-13. **Status:** accepted; exact on synthetic data, not yet run on the real panel (T-4586). Issues #140 and #142 under #134.

- **Context.** The card language has eleven signals and five conditions, and the engine recomputes every signal for every rule in Python. A search of a thousand rules a night needs a wider language and a faster screen, and neither may open a second path to a number.
- **Options.** (a) A new vectorised backtester with its own fills and costs. (b) Keep the engine's books, costs and checks, and replace only how entries are found. (c) Generate Python from a model's answer.
- **Choice.** (b). `research/lang.py` is a typed expression language on `features/formula.py`'s grammar: the eleven signals and four market-wide flows as fields, time-series operators, `rank`, `zscore`, `neutralize` (sector), `if`, `ts_corr`. A spec is an event rule, a cross-section rule (the top names by a score, every n-th session) or a minute rule. `research/fast_eval.py` builds each field once as a table by calling the engine's own `value`, keeps it as Parquet with `event_time` and `knowledge_time`, and `FastEngine` overrides only `Engine.events`. Old cards compile unchanged through `lang.from_rule`. Look-ahead does not compile: every field has a least delay and `check_lookahead` adds up the `delay`s above it. Complexity (tree size, free numbers, fields) is computed at parse time.
- **Why.** One cost path is the project's first rule. A test compares the table path with the engine on the ten reference rules and two hundred generated ones and requires the same entries, and one screen is compared whole. Nothing is passed to `exec`.
- **Cost if wrong.** Building a table is still one Python call per cell, so the first use of a field is slow; the speed-up is for the second rule onward and is not measured on the server yet (`make fast-eval-bench`). The store is keyed by symbol and its cache name does not hash the data (S-064). Per-stock F&O, holder, rebalance and results fields are not in the language yet, and minute rules have no screen of their own (S-065).
