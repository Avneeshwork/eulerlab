# ADR-121: Pin PostCSS 8.5.32 under Next with an npm override; leave the ESLint minimatch advisories

- **Context:** After ADR-118, `npm audit` in `web/` (2026-11-02, T-4379) listed 20 advisories. Two came from PostCSS 8.4.31, which Next 15.5.28 pins exactly to build our CSS (1 high: GHSA-qx2v-qp2m-jg93, GHSA-6g55-p6wh-862q, GHSA-fxqj-rqcc-2cmp, GHSA-r28c-9q8g-f849; plus the moderate this puts on `next`). The other 18 are one advisory, minimatch < 11.0.1 (GHSA-g3hv-75wg-m249), reached only through the ESLint 8 lint toolchain.
- **Options:** (a) Next 16, as ADR-118 assumed was needed. (b) An npm `overrides` entry pinning PostCSS 8.5.32 under `next`, a minor bump in the same major. (c) For minimatch: override to 11, ESLint 9, or ESLint 10.
- **Choice:** (b) for PostCSS. Leave minimatch: ESLint 9, `@eslint/eslintrc`, `eslint-plugin-import`, `eslint-plugin-react` and `eslint-plugin-jsx-a11y` (latest, checked 2026-11-02) all still require minimatch ^3, ESLint 10 requires ^10.2.6, and no release before 11.0.1 is fixed. Forcing 11 changes minimatch's export shape under ESLint 8.
- **Why:** The override clears the only high without a major upgrade; typecheck, lint, the 25 web tests and `npm run build` pass. The minimatch flaw is a slowdown on a hostile glob pattern; the only patterns it reads are our own lint config, it runs only on the operator's Mac, and it never ships.
- **Cost if wrong:** If Next relies on PostCSS 8.4 behaviour, a CSS build could differ; the build passes today. Remove the override when a Next release ships PostCSS >= 8.5.23. Recheck minimatch when the ESLint plugins move to >= 11.0.1 (T-4379).
