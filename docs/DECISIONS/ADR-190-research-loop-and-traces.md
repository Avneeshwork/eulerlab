# ADR-190 — Every model request is kept in full, and the autopilot researches with tools before it writes

**Date:** 2026-11-14. **Status:** accepted; operator's "go ahead" on 2026-11-14 for issues #165 and #162. Tested on made-up data only; no real night has run (agents halted, T-4596).

- **Context.** A run kept its prompt's hash and its answer's length, not the prompt or the answer, so no bad night could be read back or replayed. And every agent was one model turn with no tools: the autopilot wrote ten rule specs from one prompt and never saw a figure before writing. Leading research agents (R&D-Agent(Q), arXiv 2505.15155) loop: hypothesis, test, read the result, revise.
- **Options.** (a) Keep one-shot cards and add more context to the prompt. (b) A tool loop the model drives, with read-only tools and screens on the discovery period only, every screen counted. (c) Let the model run arbitrary code now.
- **Choice.** (b), plus traces. `llm/trace.py` records every request at `assistant.chat._post`, the one connection point, scrubbed of `.env` values, with the agent and run that asked; `make agent-replay` sends one again with another model or system prompt and prints the diff. `Context.converse` runs the assistant's tool loop (`chat.ask`, now with a `toolbox`) under the agent's daily budget, the monthly rupees, the shared rules and lessons. `research/agent_tools.py` gives the autopilot `signals`, `claim_record`, `family_record` and `screen_rule`. A screen runs the engine on data cut at the constitution's `discovery_end` (2023-12-31, bars after it dropped, not only entries), writes an experiment-store row, refuses a rule already screened, and stops at 8 a run. Cards from the loop carry an `exploration` block (screens, the rule's own discovery figures, trace ids) and a red flag saying how many screens came first. If the loop fails, the one-shot prompt writes the night's cards as before. `explore: false` in `config/agents/autopilot.yaml` turns it off; `daily_requests` went from 5 to 17.
- **Why.** The model can now learn inside a run what the screen would tell it, without seeing 2024 or the forward test, and the firewall's bar rises with every look, so more search must clear more. Traces are what evals, replay and the canary need.
- **Cost if wrong.** Cards are no longer written blind: a rule may be screened on 2016-2023 before its card exists, so the full-window screen is not an untouched test of it. The experiment-store row and the card's red flag record that, and the selection year is still unseen by the loop. A loop request resends the whole thread, so it costs several times a one-shot request; on Claude Sonnet a 12-round night is more tokens than the old 5 requests. No IC, event-study, SQL or Python tool yet (S-068).
