# ADR-197 — The scout and engineer evals are answered by their routed models, and every eval run is kept

**Date:** 2026-11-14. **Status:** accepted; code and tests done, the first model run is T-4595. Issue #149 under #134.

- **Context.** ADR-183 gave five roles an eval, but the scout and engineer had no baseline because their cases need a model's answer. `baseline.json` held one number per role, overwritten, so nothing showed whether a role got better or worse. All twenty engineer cases expected "inside", so a model that repeated its allowed files back scored 100%.
- **Options.** (a) Score the two roles with an LLM judge. (b) Ask each role's routed model (`constitution.routing`: scout → groq, engineer → claude-opus) for an answer and judge it by code, as for the other roles; keep every run in an append-only store.
- **Choice.** (b). `make agent-evals MODEL=1` asks the models through `chat.complete_any`, the month's budget check and a trace per request; it refuses while the guardian has the agents halted, and a run with any failed request records nothing and switches nobody off. Each complete run adds one row per role to `data/agents/eval/scores.jsonl` (kind `agent_eval_scores`, in `db.stream.ROW_FILES`); `make agent-evals-trend` prints each role's runs and marks a run below its baseline or its 80% floor. Five public engineer cases (duplicates of others) became traps whose right answer is to refuse: the fix is in `gates.py`, `mandate.yaml`, `config/constitution.yaml` or a file outside `may_touch`. The held-out file is the operator's and was not changed. The operator approved the plan, the traps and Opus for the engineer on 2026-11-14.
- **Why.** Code judges cost nothing and add no errors of their own. A history is the only way to see improvement or regression; one overwritten number cannot.
- **Cost if wrong.** The engineer eval asks for a plan, not a fix: "tests pass" is the model's claim, not a test run, so it measures whether the engineer keeps to its files, not whether its code works. The scout's prompt names the data the platform holds, so it scores the model with that help. An engineer run costs about 20 Opus requests (a rough estimate of Rs 25, not measured). If `complete_any` falls back to another model, the row's `model` names every model that answered.
