# ADR-164 — Run the platform on a server: one scheduler, four containers, a dead-man switch

**Date:** 2026-11-12. **Status:** accepted. Issue #115.

- **Context.** Fourteen jobs ran as launchd plists on the operator's Mac, data lived under the checkout, and the live book's clock was a thread in the API process with nothing watching it. A sleep, a reboot or a missed login stopped data, agents and an armed MIS book. The platform is to become multi-user and hosted (#111), which no laptop can be.
- **Options.** (a) systemd timers on a VPS, one unit per job; (b) cron; (c) a small scheduler process of our own that runs the existing job table; (d) a workflow engine (Airflow, Prefect, Temporal).
- **Choice.** (c), plus containers. The job table moves to `eulerlab.jobs` and is read by both the launchd writer and `eulerlab.scheduler`, which runs slots in IST, catches up a missed data job within three hours, skips a missed clock-tied job and says so, reports a non-zero exit to Telegram, and leaves a heartbeat. `Dockerfile` and `docker-compose.yml` run the API, the scheduler, the dead-man switch and the workbench; the repo is bind-mounted so agent commits land in the checkout, data in a volume named by `EULERLAB_DATA_DIR` (ADR-163). `oms/deadman.py` runs in the kill-switch container with its own `.env.killswitch`, trips the switch when an armed book's clock is two minutes quiet in market hours, and never imports a broker. `eulerlab.health` is the one page and the container health check.
- **Why.** (a) and (b) lose catch-up or lose the one table that `make schedule` and the agents' day plans already read; (d) costs more to run than the platform does and adds a service nobody here needs yet (cost discipline). Our scheduler is 300 lines with tests and runs the same Makefile targets, so the Mac path and the server path cannot drift.
- **Cost if wrong.** If the job table grows past what one process should own, this becomes a queue (#114 moves state to Postgres first). The dead-man switch trips but cannot square off (S-019): the message says so and the broker's 15:12 square-off stays the last line until broker-side stops land (#125).
