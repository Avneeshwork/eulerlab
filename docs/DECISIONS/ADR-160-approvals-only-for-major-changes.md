# ADR-160 · Only major changes wait for the operator's approval

- **Context:** The operator asked on 2026-11-09 to "make maximum approvals automatic, just keep only major change need approval". Agents waited for a click on work that changes nothing outside the project's own task list: accepting a head's task whose steps had all passed the checklist, starting an engineering fix (it only writes a branch) or a branch review (it only reads), and "approving" notices where approval recorded nothing (a research draft the idea lab tests anyway, a fix or signal engineering could not make).
- **Options:** keep every approval; make everything automatic; split by consequence.
- **Choice:** split by consequence. Automatic now: a head closes a task as soon as every step passes the checklist (`manager.roll_up`; "Send back" still works on a closed task), `fix_code` and `review_branch` run as `auto: true` (still within engineering's `daily_requests` and `max_fixes`), and research drafts, failed fixes and uncoded signals are notices without an approve button. Still waiting for the operator: merging any code (a ready fix, a coded signal, a drafted primitive, any change to `gates.py` or `mandate.yaml`), money (portfolio weights, retiring a book, live money after a gate verdict), buying data, sending a lab survivor to the gate, applying a drafted handbook page, the idea lab's card tests and the autopilot's rule batches (both spend trials and run from the terminal), and alerts only a person can act on (for example an expired broker login).
- **Why:** an approval is worth the operator's attention only when saying no would stop something with a cost: code that runs, money, trials, or data that is paid for.
- **Cost if wrong:** engineering may spend up to its 20 daily model requests on fixes the operator would have skipped (about $0.10 per Opus request), and a head may close a task whose result the operator would have sent back; both are visible on the page and reversible.
