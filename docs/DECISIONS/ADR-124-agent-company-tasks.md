# ADR-124: The heads become working managers: tasks, daily plans and a capability check

- **Context:** On 2026-11-03 the operator asked that every agent plan its work and have defined everyday tasks; that the CEO can give a task to a manager, who allots it to agents; that the org chart becomes a family tree where clicking someone shows their tasks and today's tasks; that everything is transparent; and that each agent is checked for being able to do its work. They chose "AI first, fixed rules on fallback" for the managers, and Groq as the AI; then asked that agents working by rules get AI help when they are stuck.
- **Options:** (a) Heads as plain functions outside the agent runtime. (b) Heads as agents (`config/agents/head_<dept>.yaml`, `reports_to: ceo`, worker `workers/manager.py`), with tasks as an append-only event log and a separate work runner that starts agents. (c) Let a head start its agents' runs itself.
- **Choice:** (b). Each head is an agent with a budget, the hash-chained log and the doctor. It checks finished tasks against a fixed checklist (sends one back at most twice, then blocks it for you), passes finished parents up, splits new tasks by asking Groq (`provider: groq`) and falls back to each skill's `words` when Groq is unavailable, out of budget or names agents that are not on the roster, and writes every agent's plan for the day. When a task is blocked, its head asks Groq for help once (again each time you press Ask AI for help): Groq reads what the agent returned and either fixes the task (a corrected value, or another agent and kind on the team), which puts it back to assigned, or writes you a diagnosis; without Groq it stays blocked. This is how the agents with no model (data, operations, portfolio) get AI help. A model that read the roster and said nothing fits is believed: the task is blocked for you. Agents list `duties` and `can_do` skills; only an `auto` skill is started by `agents/work.py`; the lab (spends trials, terminal-only) and engineering (paid model, writes branches) wait for you. Tasks live in `data/agents/tasks.jsonl`; a state change that does not fit is refused. `agents/capabilities.py` checks by reading that every skill's argument is read by its worker.
- **Why:** (a) would bypass budgets, the log and the doctor. (c) would make a head's run as long as its slowest agent and put two kinds of work in one run; a separate runner keeps the head quick and the calendar honest (it reads agent runs from the Makefile). No task kind reaches the gate, the ledger, the holdout or the order path, because no agent lists one.
- **Cost if wrong:** The fallback word lists are chosen by hand (A-093) and can route a task to the wrong agent; the head's checklist then sees a run that did not answer the task only if the run failed, so a wrong-but-ok run is passed up and you see its summary before closing it. Groq's free per-minute token limit can stall model-heavy agents (research 142, T-4402).
