# ADR-132: The data agent runs a fixed routine every two hours; a watchdog checks every agent; every model request's tokens are logged

- **Context:** On 2026-11-03 the data agent graded data but never fetched, called today's not-yet-published data "missing", and could not see 12,107 files the nightly upload refused every night because each differed from its B2 copy (two news months held 1,552 rows B2 lacked). The operator asked for a fixed procedure: download, fix issues with AI help if needed, no duplicates, delete local once in B2, check every two hours 06:00–20:00 IST; and for every agent to be checked for errors, wrong work and excess tokens. Only request counts were recorded, not tokens.
- **Options:** (a) Keep the data agent a grader and fix the uploads by hand. (b) Delete local files that differ from B2. (c) Merge each differing file into B2's copy (rows once, earliest knowledge time), then delete it; give the data agent a fixed routine with one Groq diagnosis for what is left; add a watchdog agent across runs; log tokens per request.
- **Choice:** (c). `ingest/merge_back.py` merges and deletes, in `make daily` (not ignored, so a file it cannot merge fails the run and reaches Telegram) and in the data agent's upkeep. The data agent re-runs allowed steps (`auto_rerun: true`), runs upkeep under the `feed` lock, and asks Groq once (8 a day) whether to re-run one allowed step, give the problem to the Head of Data and Platform as a task, or tell the operator. `make schedule JOB=data-watch` runs it at 06, 08 … 20 IST. `agents/workers/watchdog.py` (after the 08:45, 16:15 and 17:00 runs) flags failed, stuck and missed runs, requests and tokens over budget, and blocked, returned or overdue tasks; it re-runs once a day only data, operations, portfolio and knowledge_keeper, and asks Groq once (4 a day) who should fix the rest, which becomes a task for the agent's head. `llm/usage.py` logs every request's tokens by agent and run; `output.json` carries `tokens`. Heads now also check that a research or lab task delivered something (`manager.DELIVERS`).
- **Why:** (a) left the backlog growing and B2 missing rows. (b) would have lost those 1,552 rows. (c) keeps every row, leaves B2 the store of record (its replaced object stays as an older version, A-098), and every remedy is from a fixed list: the model diagnoses and routes, it never runs anything.
- **Cost if wrong:** A row that changed only in a time field is kept once at its earliest knowledge time; two rows that differ only in `knowledge_time`/`receipt_time` but were meant as two records would be collapsed (A-101). About 12,000 B2 downloads to clear the backlog (class B, 2,500 free a day, then $0.004 per 10,000). Up to 12 more Groq requests a day.
