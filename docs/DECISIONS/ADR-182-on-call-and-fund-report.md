# ADR-182 — On-call fixes dead letters from an allowlist, reconciliation trips reduce-only, and a fund report goes out each close

**Date:** 2026-11-13. **Status:** accepted; tested on planted failures only, not yet five sessions on the server (T-4594). Issue #148 under #134.

- **Context.** The data agent, watchdog, doctor and guardian found problems, but a person fixed them. Paper books were reconciled only when someone ran the report. Nothing summed up the fund each day.
- **Options.** (a) Let an agent choose any fix, with a model. (b) Three fixed remedies, everything else a ticket, no model.
- **Choice.** (b). `oncall.py` runs under the watchdog (role on_call) but lives outside `agents/`, since it reconciles books and trips paper kill switches, which agent modules may not import (`agents/boundaries.py`): a dead letter that names feed steps is re-run through `agents/jobs.py`'s allowlist; `reconcile` and `trip_kill` (paper books only) are the other two; anything else is a task for the engineering agent with the error. Each incident is a row in `data/agents/incidents.jsonl` and a dated line under "Incidents" in its runbook (a new runbook is written when none exists). A letter is settled only when the fix worked or the ticket was opened. Each close, every active paper book's journal is compared with its broker; any break opens a reduce-only window (`loss_limits.start_reducing`) and pages the operator. `fund_report.py` keeps the day's NAV, P&L by strategy and rung, drawdown against each halt level, ladder moves, incidents and AI spend, and sends eight lines to Telegram. Both run at the end of `make agents-close`.
- **Why.** A fix chosen by a model is a fix nobody reviewed. The three remedies are already safe to repeat; the rest needs code, which is the engineer's job.
- **Cost if wrong.** "Restart a job" is not a separate remedy: a durable job resumes from its last kept step the next time its schedule runs it (ADR-174), so on-call does not start it early. Slippage is not in the report yet, because the live-price shadow keeps no daily figure (T-4594). A runbook line is written to the working tree and committed with the next commit, not by on-call.
