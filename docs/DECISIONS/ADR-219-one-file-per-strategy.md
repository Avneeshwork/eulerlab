# ADR-219 — One file per strategy, one file per sizing model

**Context.** Operator, 2026-11-17: "I wanted everything modular like in one strategy folder we have separate files for all strategies, similarly in risk model all separate files for position sizing models etc it will give better understanding and concise view to other developer". Strategy rules were spread over nine modules of up to 1,560 lines (`backtest/india_papers.py`, `evidence_daily.py`, `github_daily.py`, `events_daily.py`, `screener_models.py`, `published.py`, `intraday/papers.py`, `india.py`, `crypto_signals.py`), the 45 screen studies sat among the intraday engine's own files, and the sizing models and loss limits were inside `deploy/`.
**Options.** (a) Leave the modules and write an index page; (b) one package per family under `strategies/`, one file per strategy, a `common.py` for what the family shares and an `__init__.py` that lists them in library order; (c) one flat folder of 150 files.
**Choice.** (b). `strategies/daily/<family>/<strategy_id>.py` holds one strategy's rule and its library entry (the `STRATEGIES` tuple at the bottom; `SPECS` in `screener`; `SPEC` and `RESEARCH` in `published`). `strategies/intraday/<family>/<signal_id>.py` does the same for minute signals (`SIGNALS`). `strategies/studies/<name>.py` is one screen study each (a study can test several rules from one research note and is not split further; `strategies/studies/__init__.py` is the old `studies.py` list). Sizing and risk live in `risk/sizing/` (one file per model, plus `caps` and `capital_fit`), `risk/limits/loss_limits.py` and `risk/book/` (one file per measure; same import path as before). The old module paths are shims that hand back the same objects (`tests/test_moved_import_paths.py`) for code on other branches; all code in the repo imports the new paths. A script did the split: it copies statements verbatim, only moves them between files, and moves a function into a strategy's file only when nothing else uses it.
**Why.** A developer reads one file to understand one strategy, and a new strategy is one new file plus one line in its family's `__init__.py`. Nothing behaves differently: the registry (160 entries), the 85 daily builders and their target weights on a seeded panel at four dates, the 24 intraday signals' verdicts on seeded candles, the studies list and every sizing rule's weights were dumped before and after the move and are byte-identical. The library entries keep their old indentation (a one-item tuple, not a bare call) so that a strategy's version-lock hash (ADR-087), which hashes source text, does not change: all five deployed daily strategies keep their hashes.
**Cost if wrong.** 33 deployed intraday cards hash whole modules (`rule_engine`, `rule_book`, the studies) whose import lines changed, so they would report "code changed". `make relock-moved` (`tools/relock_moved.py`) relocks a deployment only when its lock equals the hash of the code just before the move, keeps the old hash in the lock's history, and leaves anything else for review; it reports unless `APPLY=1`. Branches written before the move that edit a moved file must re-apply their change in the new file. A test that monkeypatches a helper must patch the module that looks it up (`events.common`, a strategy's own file), not the family package. Remove the shims once no open branch needs them (T-4675; relock: T-4676).
