# ADR-088: FII/DII cash flows from NSE's own daily figure, not scraped from scanx

- **Context:** The operator asked for a scraper for everything on scanx.trade's FII/DII page that EulerLab does not hold, shown on the dashboard. EulerLab already lands NSE participant-wise OI (FII/DII/Pro/Client derivatives positioning). It holds no cash-market flows (T-4163). scanx.trade, its robots.txt and its terms could not be fetched from the build session (proxy 403 from both the cloud container and the operator's machine VM; research 126).
- **Options:** (a) scrape scanx.trade's page; (b) capture NSE's `fiidiiTradeReact` each evening, forward only; (c) backfill history from an aggregator (Trendlyne, ADR-009) or NSDL's FPI reports.
- **Choice:** (b). One request per run in `make daily`, `make india-live` and the coverage button; landed under `data/landing/fii_dii/`, graded by the data quality contract, appended to `data/derived/fii_dii_cash.jsonl`, shown in a self-contained panel on the Big money tab.
- **Why:** NSE is the publisher; scanx and every other aggregator republish its provisional figure, so (a) adds a dependency and a terms question (the ADR-009 lesson: robots.txt is not permission) without adding data. NSE is already inside ADR-006's accepted scope. (c) is not dropped: NSDL is official and historical but its format and terms are unread (T-4186).
- **Cost if wrong:** History starts on the first evening it runs; a missed evening is lost for good, because NSE serves today only. If scanx shows something NSE does not publish, that part is still missing (T-4187). If NSE's field names differ from A-070, the first run reports `malformed` and lands nothing.
