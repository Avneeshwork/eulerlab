# ADR-165 — Storage for a multi-user platform: Postgres for state, object storage for data

**Date:** 2026-11-12. **Status:** proposed (design only; implementation is issue #114). Depends on #112, #113.

- **Context.** State is files under `EULERLAB_DATA_DIR`: OMS journals, deployments, the trial ledger, agent memory, results. One machine can own them; many users on several servers cannot. Market data (about 4.5 GB, 23,000 objects) is already mirrored to Backblaze B2, which is the store of record.
- **Options.** (a) Keep files, one directory tree per user, shared through a network volume; (b) Postgres for everything, data included; (c) Postgres for transactional state and object storage (B2/S3, Parquet) for market data, behind one data-access layer; (d) a warehouse (ClickHouse, BigQuery).
- **Choice.** (c). Postgres holds users, workspaces, broker connections (encrypted columns), deployments, orders and the OMS journal, the trial and search ledgers, agent tasks and logs, each row with `workspace_id`, `event_time` and `knowledge_time`. The append-only rules become constraints and triggers: the ledger and the kill-switch log accept inserts only, and the hash chain is checked by a trigger. Landing files stay immutable in object storage; derived panels move from JSON lines to Parquet in the same bucket, read through one layer that enforces `as_of` and `workspace_id` structurally, as `BitemporalStore` does today. Migration is a one-off tool from today's files, per install. The self-hosted path gets the same shape with Docker Compose adding a `postgres` service and a local S3-compatible store (MinIO) or B2.
- **Why.** (a) breaks under two servers and gives no transactions for orders. (b) puts gigabytes of bars in the wrong tool. (d) is cost and operations the platform does not need until a measured query is too slow (cost discipline). One managed Postgres and one bucket carry hundreds of workspaces.
- **Cost if wrong.** The data-access layer is the hedge: every module reads through it, so swapping Parquet-on-B2 for a warehouse later touches one package. If Postgres becomes the bottleneck for minute bars, that is the measurement (d) waits for.
