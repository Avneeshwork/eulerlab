# ADR-150 — The research autopilot: one rule language, one screen, a nightly loop

**Context.** Operator, 2026-11-07: they have to ask for every step, and the agents cannot run research alone. An audit found that the idea lab only tests monthly formula rankings, while every recent pass (H-0161, H-0168, H-0096) is an event rule on other data; each manual batch (research 166-176) needed a new hand-written screen. The lab tested 2 of 37 queued cards on 2026-11-07 (one card took 2.5 hours). Nothing checked for the biases the manual batches caught by hand (HISTORY #82, #84, research 174, H-0172's zero events). The operator approved a plan and chose Claude Sonnet first with Groq as fallback ("go").

**Options.** Make the lab smarter on formulas; keep writing a screen per batch; or make a rule a data spec that one engine runs, and automate the loop around it.

**Choice.** `intraday/rule_engine.py`: a card's `engine:` block (signals from a fixed vocabulary, a side, a rank, intraday or an N-session swing) run in research 173's frame, with lookahead refused at parse time (a close needs `lag >= 1`), a window the card cannot choose, and five bias checks on every screen. It reproduces research 176's ten results exactly. `agents/workers/autopilot.py` writes ten cards a night (Claude Sonnet, then Groq, then fixed rules). `research/autopilot.py` commits them before any run, screens them, gates clean survivors through the unchanged `make validate` and `make gate` within `gate_entries_per_week` (10, operator's to change), and for PROMOTE or PAPER stores the library report and starts a paper book (`deploy/engine_book.py`). It writes one research note and one commit, and sends one summary to the inbox and to Telegram. It runs in `make agents-ideas` after research, before the lab.

**Why.** The creative step (which rule to try) is the model's; everything that decides a result is fixed code that a test pins. A new idea needs no new code, so the loop can run without a person.

**Cost if wrong.** More rules tried means more false passes the simple gate does not correct for: about ten more each night. The weekly allowance caps the ledger entries, not the screens. Engine rules see only daily bars, so the official open and close stand in for fills. A paper book starts without the operator's click (paper only), and live money stays theirs. Gating runs outside `agents/` because the boundary forbids agents the gate. The model writes only YAML that code validates, but the loop it starts does append to the ledger.
