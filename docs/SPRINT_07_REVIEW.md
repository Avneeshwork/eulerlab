## The scope change you should know about

The build plan verifies this sprint "on your recorded chains" — the intraday
recorder from Sprint 2, which has now been deferred four times and has never
run. There are no recorded chains.

So these checks run on **end-of-day F&O bhavcopy** instead: 2,868 days of
every strike, expiry and right with a settlement price. The mathematics is
identical on a daily snapshot; only the resolution differs. Recorded as
ADR-018 rather than done quietly, because it changes what the sprint can find:
EOD data can expose stale marks, inverted price ladders and impossible
settlement prices, but it cannot show intraday arbitrage — which is where most
genuine violations live, and the thing the recorder would actually earn.

## What now works (plain English, no jargon)

- **It finds option prices that cannot all be true at once.** If a butterfly
  costs less than nothing, or a call gets more expensive as the strike rises,
  someone could take free money — so at least one price is wrong. These are
  hard inequalities, not settings I picked, which means a violation is a fact
  rather than an opinion.

- **It works out the fair forward price from the chain itself.** Checking
  put-call parity normally needs an interest rate, which we do not have.
  Instead the rate and the forward are both *recovered* from the option prices
  by fitting a line through them. Nothing is assumed, and no invented number
  can quietly become the thing being measured.

- **It computes our own implied volatility** rather than trusting a vendor's,
  using Black-76 — the futures-based model, correct for Indian index options,
  which are European and cash-settled. When no volatility can produce the
  quoted price, it says so instead of returning a number, because that failure
  *is* the finding.

- **It separates traded from untraded contracts, and this matters more than it
  sounds.** NSE publishes a settlement price for every listed contract,
  including strikes nobody traded all day — those are NSE's model output, not
  market prices. Checking them would mostly measure NSE's model. The default
  is traded-only; including the rest is a deliberate flag.

### The bug this sprint found, which is the same bug as last sprint

The fitted forward is the yardstick every parity and intrinsic check is
measured against. I first fitted it with ordinary least squares.

A test planted one call at ₹1 when its true value was about ₹1,000. The fit
was dragged so far off that its output failed a sanity range, the fit gave up,
and the check reported **nothing at all**. The corrupted price hid itself
perfectly by destroying the instrument meant to detect it.

That is precisely the standard-deviation failure from Sprint 6 in different
clothes — an estimator that one bad value can move arbitrarily. Same answer:
a median-based fit (Theil-Sen), which tolerates roughly 29% of the points
being wrong. The test now pins both that it survives one bad quote and where
it stops coping, so the claim is bounded rather than boastful.

## What I could not verify

- **Anything about real option prices.** This is the honest headline. The
  checks find every violation I plant and none on a clean chain, which is
  necessary and not sufficient.
- **Whether the calendar check is sound.** For European options on futures,
  different expiries reference *different* futures, so the textbook "longer is
  worth more" inequality is not guaranteed. I made it WARN-only and fire just
  on large inversions, but I have not confirmed that the survivors are real.
